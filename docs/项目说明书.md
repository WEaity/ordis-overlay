# Warframe 本地助手 · 项目说明书

> 版本：v1.11 ｜ 更新：2026-10-21 ｜ 适用：Windows 10/11 + 国际服 PC

---

## 1. 项目简介

一个**跑在本机的 Warframe 桌面悬浮助手**。它在游戏画面上悬浮一个 90px 的全息晶体图标，点开是一个磨砂面板，可以：

- 用自然语言问装备属性、市场价、掉落来源、世界状态、配卡思路；
- 按 `Ctrl+V` 粘贴任意截图（奖励界面 / 装备界面 / 聊天截图），直接识别并给结论；
- 开核桃（遗物）时一键选出「该拿哪个」，0.8 秒出结果。

它由四层组成：**Electron 悬浮窗（前端）→ Express 服务（后端）→ 大模型 Agent（Ordis 人设）→ 两个 MCP 数据服务（26 个工具）**。

### 它是什么

- 一个**只读**的信息查询工具：查价、查掉落、查属性、查世界状态、算遗物收益。
- 一个**本地优先**的应用：数据表存本地，价格与状态走公开接口，识别用你自己的 API Key。
- 一个**单人自用**的桌面小工具，不需要服务器、不需要账号体系。

### 它不是什么

- ❌ 不读游戏内存、不注入进程、不做自动化操作（不自动交易、不自动点击）；
- ❌ 不代替你发消息：密语只生成可复制文本，由你自己粘贴；
- ❌ 不做账号交易、代练、代充相关任何事（见 §11 安全红线）；
- ❌ 不联网上传你的库存数据：库存只在本机 MCP 进程里读。

## 2. 设计目标

| 目标 | 落地方式 |
|---|---|
| **不打扰** | 无边框 + 透明 + 点击穿透 + 置顶；不用时常驻一个 90px 的小图标 |
| **快** | 本地数据表 + 工具结果缓存 + SSE 流式输出；遗物查表 1–3ms |
| **不瞎编** | 所有可变数据必须来自工具；查不到就标注「不可读/不可达」，不许估算成事实 |
| **可解释** | 每条结论都带数据来源（market v2 / DE 官方 / 灰机 wiki / 本地库） |
| **可维护** | 前后端分层、数据管道独立成脚本、每个数据表可单独重建 |

## 5. 关键实现

### 5.1 悬浮窗主进程（`main.js`，734 行）

- **窗口**：`transparent: true, frame: false, skipTaskbar: true, alwaysOnTop: 'screen-saver'`，`backgroundColor: '#00000000'`。
- **两级尺寸**：收起 `BUBBLE`（默认 90，范围 80–150），展开 `EXPANDED`（384×400，可拉伸）。窗口右下角固定为锚点，展开时向左/向上长，收起时缩回。
- **点击穿透**：`setIgnoreMouseEvents(true, { forward: true })`，主进程每 150ms 轮询光标位置，命中图标区域才 `setIgnoreMouseEvents(false)`。
- **拖动**：不用 `-webkit-app-region: drag`（透明窗口 + 缩放动画下会失灵），改为页面 `mousedown → overlay:drag`，主进程 `setPosition(snapPos(x), snapPos(y))`；`snapPos` 把坐标对齐到 4 的倍数，规避 125% DPI 下的半像素累积（否则每拖一次窗口会胖 2px）。
- **缩放**：面板把手 `overlay:resize`、图标把手 `overlay:bubble-resize`，都做边界 clamp 与锚点重算。
- **锁定**：遗物模式下 `relicLocked = true`，跳过「离开 1 秒收起」。
- **后端托管**：启动时探测 3000 端口，空闲则 `spawn(process.execPath, ['server.js'], { env: { ELECTRON_RUN_AS_NODE: '1' } })`，stdout 写 `server.log`；退出时 `taskkill /PID <pid> /T /F`。
- **wiki 桥接**：隐藏窗口 `persist:huiji` 会话加载 `warframe.huijiwiki.com`，等 Cloudflare 挑战通过后在窗口内同源 `fetch` MediaWiki API，对外暴露 `127.0.0.1:3001` 的 `/search` `/page` `/raw` `/pages`。
- **单实例**：`app.requestSingleInstanceLock()`。

### 5.2 渲染层（`index.html` 946 行 + `style.css` 1197 行）

- 全透明页面，`#panel` 用 `rgba(20,22,25,.86)` + `backdrop-filter: blur(10px)` 做磨砂；边框 1px `rgba(255,255,255,.28)`，直角为主。
- 图标区**禁止任何底色/边框/阴影**（`#bubble` 及子元素 `background/border/box-shadow/backdrop-filter: none !important`），否则透明窗口里会露出方框。
- 展开动画从 `scale(0.92)` 起，不用更小的值——小值会在图标旁闪出一个方块。
- Markdown 用本地 `vendor/marked.min.js`（不依赖 CDN），渲染前 `sanitize()` 去掉 script/iframe/on* 事件。
- 遗物模式：🎁 按钮高亮 + 暖色内框 + 右下角圆点；粘贴图片自动识别，不用手动点发送。

### 5.3 服务层（`server.js` 374 行）

Express 5，默认 `127.0.0.1:3000`。路由清单见 §8。

### 5.4 Agent 层（`lib/agent.js` 183 行）

- **人设**：Cephalon Ordis（自称 Ordis、称呼 Operator、偶发「[系统故障：充满敌意]」+ 立刻道歉），只影响语气，不改事实。
- **系统提示词**包含：强制工作流（问「今天做什么」必须先查库存 + 世界状态）、掉落与遗物常识（来自 drop.wf.wiki 的公开数据）、输出规范（Markdown、标数据来源、密语格式）。
- **工具裁剪**：`TOOL_ROUTES` 用关键词把 26 个工具按意图分桶（查价 / 属性 / 掉落 / 库存 / 配卡 / 世界状态 / 遗物），每轮只把相关工具发给模型，降低 token 与误调用。
- **工具循环**：最多 6 轮，每轮收集 `tool_calls` 并发执行（同一轮多个调用并行），结果以 `role: tool` 回填。
- **结果缓存**：库存类工具 45s / 精通 300s / 配卡 30s，只缓存成功结果，日志标「缓存命中」。
- **SSE**：`stream: true` 时逐块 `res.write('data: {...}\n\n')`，事件类型 `delta` / `done` / `error`。

### 5.5 MCP 工具层

两个 stdio MCP 服务，共 **26 个工具**：

**wf_market（自研，15 个）**：`get_item` `get_warframe` `get_weapon` `get_mod` `check_market` `search_drops` `farm_guide` `compare_weapons` `search_items` `search_wiki` `recommend_build` `world_state` `relic_drops` `beginner_guide` `daily_picks`

**wf_inv（AlecaFrame，11 个）**：`get_alecaframe_inventory` `get_owned_inventory` `get_mastery_fodder` `get_frame_build` `analyze_build` `get_riven_mods` `get_riven_auctions` `get_syndicate_standings` `get_focus_progress` `can_craft` `search_market_item`

> 已下线（数据源不可达，注册时跳过并在日志说明）：`search_builds`（Overframe 403）、`search_community`（Reddit 被墙）、`get_worldstate`（warframestat 403）、`get_simaris_target`、`get_void_trader`、`get_relic_rewards`、`get_relic_value`、`get_farming_recommendation`。

实现要点：
- 参数归一化 `normalizeArgs()`：`item/query/name/weapon` 互为别名，避免模型换个参数名就查错物品。
- market 物品清单 12 小时缓存 + 启动预热，`check_market` 冷启 5.2s → 1.2s。
- 世界状态双源并行（DE 官方 + tenno.tools），7 秒超时；失败用 6 小时文本快照并标注时间；60s 缓存 + 55s 后台预热。
- 遗物查表纯本地，OCR 只负责认字。

### 5.6 数据管道

| 脚本 | 产物 | 说明 |
|---|---|---|
| `update_relic_rewards.js` | `data/relic_rewards.json`（1.2 MB） | 抓 drop.wf.wiki，799 遗物 / 4795 奖励，同遗物同奖励去重，四档概率合并 |
| `update_relic_parts.js` | `data/all_relics.json` | 612 条部件（离线库 533 + 奖励库补 79），拼中文全名，估算缺失杜卡德 |
| `update_relic_prices.js` | `data/relic_prices.json` | 逐条打 market v2，取最便宜 8 单中位数，剔除低于中位 30% 的钓鱼单 |
| `tools/build_zh_map.js` | `data/relic_zh.json` | 灰机 wiki 的中英对照表（tabx 467 条 + Prime 子页） |
| `tools/fill_zh_search.js` | 补进 `relic_zh.json` | 英文页名找不到时，用 wiki 搜索拿中文标题 |

**杜卡德估算规则**：离线库没有杜卡德的条目，按完好遗物基础概率分档——铜（≥20%）15、银（≥6%）45、金（<6%）100。对 526 条已知数据回测准确率 **89.9%**，结论里一律标注「约 xx（估算）」。

### 5.7 安全红线

服务端硬拦截（不调模型、不调工具、2ms 返回固定警报）：

```
淘宝 | 闲鱼 | 代充 | 代练 | 代肝 | 代打 | 代刷 | 共享账号 | 租号 | 卖号 | 买号 | 黑金 | 买白金 | 刷白金
```

命中即返回两段固定文案（风险提示 + 请通过官方渠道），不延伸话题、不推荐商品。

## 12. 已知限制

1. **灰机 wiki 依赖隐藏窗口过 Cloudflare**：挑战失败时 `search_wiki` 自动回退本地数据并标注，不会报错。
2. **world_state 依赖境外接口**：DE 官方与 tenno.tools 都不可达时，用 6 小时快照并标注时间。
3. **15 条遗物条目无价**：market 上不可交易或没有挂单（Forma / Kuva / 少数入库武器部件），属正常。
4. **14 条无中文**：Kavasa 套件等离线库命名异常的条目，需人工补名。
5. **杜卡德 79 条为估算**（准确率 89.9%），结论里已标注「约」。
6. **突击词缀仍是英文原文**（`Weapon Restriction: Pistol Only`），未做中文化。
7. **OCR 受截图质量影响**：界面文字被聊天遮挡、分辨率过低时可能漏卡；漏识别时不会硬凑数。
